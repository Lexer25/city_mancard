# Модуль Mancard — Управление организациями и сотрудниками

07.10.2026
Вер 1.1.3
[+]
Модальные окна модуля переведены на jQuery UI dialog (static/css/jquery-ui.css): окно сотрудника (views/mancard/edit_person.php) вместо Bootstrap modal, новое окно организации (views/mancard/edit_org.php) вместо prompt(), новое окно подтверждения удаления сотрудника (views/mancard/delete_person.php). Общие стили окон — views/mancard/modal_common.php: заголовок с кнопкой закрытия, слой затемнения, кнопки в панели кнопок окна, окно выше фиксированного меню Bootstrap.
В окне сотрудника поля сгруппированы в блоки «Личные данные», «Контакты», «Документы», «Служебная информация»; добавлены проверка обязательных полей, индикатор загрузки, подпись организации и сохранение по Enter.
Кнопки выбранного элемента перенесены в шапку панели «Свойства», бейдж типа элемента («Организация» / «Сотрудник») — у заголовка «Свойства»: для организации «Редактировать» (окно организации), «Добавить подразделение» и «Добавить сотрудника» (окно сотрудника с подстановкой выбранной организации), для сотрудника «Редактировать» и «Удалить». Кнопки строятся в renderPropsActions() и скрываются на время загрузки свойств; статическая кнопка «+» и блок кнопок внизу панели убраны.
Добавлено удаление сотрудника: кнопка в шапке «Свойств» и иконка корзины на строке сотрудника в дереве (при наведении, как у организаций) — подтверждение в jQuery UI окне с ФИО, ID_PEP и предупреждением, что вместе с сотрудником удаляются все его идентификаторы (карты). Используется AJAX-эндпоинт mancard/delete_person/{id} (Model_Mancard_People::deletePerson()).
Ветка дерева и панель «Свойства» обновляются без перезагрузки страницы после сохранения и удаления: window.mancardRefreshAfterPersonSave(), mancardRefreshAfterPersonDelete(), mancardRefreshAfterOrgAdd(), mancardRefreshAfterOrgRename(). Счётчики 👤 и 📁 на узле обновляются вместе с веткой, после добавления подразделения новая организация раскрывается и выбирается, после удаления выбранного сотрудника панель «Свойства» переключается на его организацию.
Перед созданием окон возвращается метод $.fn.button из jQuery UI (Bootstrap подключается после jQuery UI и перекрывает его своим плагином), поэтому кнопки окон и иконка закрытия рисуются штатными средствами jquery-ui.css; bootstrap-овский data-api [data-toggle="button"] продолжает работать.
[*]
У корневой организации два списка .tree-children (подразделения и сотрудники), а renderNodeChildren() заполнял оба — при перечитывании ветки корня содержимое дублировалось. Теперь подразделения идут в первый список, сотрудники — во второй; условие подгрузки корня ($('#root-children')) заменено на реальную проверку, лишний AJAX-запрос при загрузке страницы убран.
В PHP-разметке корневых сотрудников не было data-person-id / data-org-id — клик по ним в дереве не срабатывал; добавлено. Клик по кнопкам действий в строке сотрудника больше не выбирает сотрудника.
Раньше после сохранения сотрудника вызывалась несуществующая loadPeople() и возникала ошибка JS; из edit_person.php удалён мёртвый код окна массового перемещения (#move-dialog / #btn-move-confirm) — move_dialog.php в index.php не подключается.
